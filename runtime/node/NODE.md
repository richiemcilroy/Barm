# Node.js built-ins for npm packages

npm packages run on JavaScriptCore and expect Node.js's built-in modules (`path`, `events`, `buffer`, `util`, `stream`, ...). This directory provides them as CommonJS modules. The npm bundler includes a module only when something requires it (`crates/barm/src/npm/node_shims.rs`). Inside these modules, `require(id)` resolves only to other modules here, so `internal/...` is out of reach of packages.

## Where the code comes from

Most files are Node.js's own `lib/` files (MIT, see Node.js's LICENSE), from **v26.3.0**, as they are. `scripts/node-import.sh lib/<file>.js` copies one in. It adds a line at the top that gives the file what Node.js gives its own modules:

- `primordials`: the built-ins' original functions. `internal/primordials.js` is Node.js's `internal/per_context/primordials.js`.
- `internalBinding(name)`: Node.js's way into its C++. Here it loads `internal/bindings/<name>.js`, Barm's version of that binding: JavaScript for now, with natives into Barm's runtime where speed or the OS needs them.

Per-context files also get `privateSymbols` and `perIsolateSymbols`.

`diagnostics_channel.js` comes from Node.js v22.20.0. v26's uses `using` declarations, which JavaScriptCore doesn't parse yet (`NODE_VERSION=v22.20.0 scripts/node-import.sh ...`).

## Barm's own files

- `internal/bootstrap.js` provides `primordials` and `internalBinding`. Its table of bindings is regenerated by `scripts/node-bindings-table.py`.
- `internal/bindings/*.js` are the bindings:
  - **Written:** `buffer`, `string_decoder`, `types`, `util`, `constants`, `config`, `performance`, `messaging`, `trace_events`.
  - **Placeholders:** the rest, from `scripts/node-stub-binding.sh`. They load, and throw `ERR_NOT_IMPLEMENTED` when used.
- `internal/options.js`: a Barm program has no Node.js flags, so every option has its default.
- `internal/errors/error_source.js` finds the source expression for `assert`'s "evaluated to a falsy value" message. It scans the line rather than using acorn, and reads the source through `globalThis.__barm_source(file)`.
- `internal/bootstrap/realm.js` lists the built-in module ids.
- `internal/v8/startup_snapshot.js` reports that Barm builds no snapshots.
- `crypto.js` replaces Node.js's, which binds all of OpenSSL. It runs on BoringSSL through `__barm_native.crypto` (`runtime/crypto.c`). It covers hashes, HMAC, random values, `pbkdf2`, `scrypt`, `hkdf`, `timingSafeEqual` and `subtle.digest`, answering and failing as Node.js does. A program whose bundle has `crypto` links BoringSSL's libcrypto, not the TLS client.
- `internal/barm/random.js` provides `getRandomValues` and `randomUUID` for the global `crypto`, without loading `crypto`. Without BoringSSL linked, they use the system's `arc4random`.

## Local edits to Node.js files

- `internal/util/types.js`: `isKeyObject` and `isCryptoKey` answer false without loading `internal/crypto/keys` (Barm's crypto has neither yet).
- `internal/primordials.js`: defines `Symbol.dispose` and `Symbol.asyncDispose` when the engine lacks them (JavaScriptCore does), as Node.js once did.
- `internal/util/debuglog.js`: `testEnabled` is initialized on first use when startup hasn't done it.
- `internal/util.js`: `getInternalGlobal()` returns the primordial `RegExp`, `Object` and `Array` rather than a second realm from `vm` (none yet).

## Known differences

- `util.inspect` of a settled promise shows `Promise { <pending> }`. A promise's state isn't visible from JavaScript, and JavaScriptCore's public C API doesn't expose it.
- `util.inspect` can't see a proxy's target or iterator entries (`getProxyDetails`, `previewEntries`).
- `crypto` has no ciphers, signatures, key objects or Diffie-Hellman yet: those functions throw `ERR_METHOD_NOT_IMPLEMENTED`. `crypto.subtle` only digests.

## Tests

`scripts/node-shims.sh [name...]` runs each `tests/node/<name>.js` under Node.js and under a bare JavaScriptCore (the system `jsc`), with these modules behind `require()` (`tests/node/harness.js`). Standard output must match.

`scripts/node-resolve.sh <name>` runs a test and imports each Node.js file it finds missing, stubbing missing bindings, until nothing is missing.
